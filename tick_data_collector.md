#### 1. Назначение и функционал
мы создаем проект для сбора тиковых данных с терминала MetaTrader 4. папка проекта F:\Projects\tick_data_collector. Советник собирает тиковые данные в оперативную память, передавая их в TickSenderApi.dll. TickSenderApi.dll асинхронно, параллельно с работой советника отправляет эти данные на сервер. сервер передает данные в базу данных и возвращает ответ.
#### 2. Стек технологий и версии
Стек технологий: Советник на mql4, TickSenderApi.dll на C++, сервер на Java, база данных на PostgreSQL. Версия Java: 25. Архитектурный подход: чистое разделение. Инструменты: без Spring Boot, чистый java.
#### 3. Формат взаимодействия
Протокол: REST API (HTTP). Формат данных: JSON

#### 7. Принцип работы и взаимодействия советника и dll
советник накапливает определенное количество элементов массива структур тиковых данных, добавляет их в dll в массив передачи и обнуляет свой массив. асинхронная функция отправки данных внутри dll сканирует длину массива передачи и если его длина достигает определенного количества, отправляет пакет данных на сервер и ждет ответ. в случае если сервер не принял данные, то функция сохраняет детализацию ошибки в переменную. перед очередной передачей данных в dll советник производит его опрос (Polling) на наличие последней ошибки отправки, и если она имеет место быть, то выводит сообщение в терминал. если сервер принял данные, то функция отправки в dll удаляет удачно оправленную часть массива передачи.
#### 8. Принцип работы сервера
подключение к базе данных на сервере должно осуществляться с использованием HicariCP. настройки подключения к базе данных должны содержаться во внешнем ini файле. для получения настроек из ini нужно будет установить зависимость ini4j. на сервере должны работать классы web listener и servlet. при запуске сервера web listener устанавливает подключение к базе данных через HicariCP по настройкам из ini и записывает во внешний лог файл статус запуска сервера (удачно/не удачно). для записи во внешний лог файл будем использовать java.util.logging. входящие запросы будет обслуживать только один сервлет.
#### 9. Блокировка работы советника на графиках одной и то же валютной пары в dll
чтобы советник не отправлял данные в случае если он будет открыт повторно на графике одной и той же валютной пары, будем использовать системный Mutex (в коде DLL) и инициализирующую dll функцию. идея защиты от дубликатов: каждая валютная пара должна иметь свой уникальный именованный Mutex. если вторая копия советника на той же паре пытается инициализировать DLL, она получает отказ и пользователю выводится соответствующее сообщение в терминале.
#### 10. Дедупликация тиковых данных
для дедупликации будем использовать схему Heartbeat. советник по таймеру будет вызывать функцию короткого запроса на сервер внутри dll. это будет пульс, за счет которого сервер будет выбирать ведущего советника. пульс будет состоять из символа валютной пары и уникального ID советника, который будет генерироваться при запуске советника. сервер выбирает ведущим тот советник, который пришлет пульс первым и далее принимает тиковые данные только от него. если же появляется другой советник, присылающий данные по валютной паре, данные по которой уже идут от ведущего советника, сервер в ответ на приходящий от этого советника пакет, возвращает ошибку.
